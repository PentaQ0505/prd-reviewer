# PRD 审查清单

按实际产品选择适用项。将缺失项归入正常、异常、边界、降级场景，并指出具体影响；不要把所有检查项都升级为必做功能。

## 场景完整性

| 类型 | 检查重点 |
| --- | --- |
| 正常 | 首次与再次使用、入口、前置条件、完成反馈、后续动作 |
| 异常 | 权限拒绝或撤销、网络中断、超时、服务失败、部分成功、写入失败、资源不可用 |
| 边界 | 空数据、单条、数量上限、最大文件、临界值、重复点击、并发请求、取消、切后台、重启 |
| 降级 | 离线、低存储、低内存、服务不可用、能力不支持时的可用功能、用户提示、恢复条件 |

## 逻辑一致性

- 检查同一术语、字段、状态、优先级、额度、价格或超时是否前后一致。
- 为关键对象列出状态、进入条件、允许动作、终止状态和失败恢复；检查无法离开或无法到达的状态。
- 检查数据从产生、读取、更新、展示到删除是否闭环；明确事实来源，避免多个模块各自保存冲突状态。
- 检查重复提交、重试、取消和超时后迟到的成功回调；明确幂等范围及重复结果处理。
- 检查部分成功是否允许、如何显示、是否重试全部或仅失败项。
- 检查图、正文、字段、接口、异常表和验收标准是否描述同一行为。

## iOS 工具类 App

将以下内容作为审查问题，具体平台能力以对应版本的 Apple 官方文档为准。

- **照片权限**：区分未请求、拒绝、受限、有限访问、完整访问，以及实际需要的读写范围；检查权限变更后刷新和提示。
- **照片来源**：检查仅云端资源、下载失败、原件不可用、格式不支持、媒体损坏、共享资源或访问范围变化。
- **照片恢复**：先定义“恢复”的来源和范围，核实是否有可用系统能力；不要默认第三方 App 能读取永久删除照片或任意系统区域。
- **清理操作**：定义重复或相似的判定、保留规则、预览确认、批量部分失败、取消、删除后统计刷新；说明可恢复性及限制。
- **AI 图像处理**：检查输入尺寸和格式、上传与本地处理边界、排队、超时、重复请求、取消、结果保存、原件保留及失败后的额度处理。
- **生命周期**：检查切后台、被系统终止、重新打开后的任务状态、进度恢复及重复执行。
- **资源与数据**：检查存储空间、内存峰值、缓存清理、临时文件、上传授权、保存期限和删除路径。
- **付费能力（仅适用时）**：检查免费额度、订阅状态、恢复购买、退款或权益变更、重复扣次、失败补偿与服务端校验边界。

## 开发可执行性

- 字段应说明类型、必填、默认值、约束、来源和生命周期；未知项标“待确认”。
- 索引建议应对应真实查询方式和预计数据规模；不要无依据增加存储或索引。
- 接口应说明调用方、前置条件、输入输出、状态变化、错误和重试策略。
- 区分业务失败、权限失败、网络失败和未知结果；不要用一个“失败”覆盖所有恢复方式。
- 技术风险应说明触发条件、影响、验证办法、降级方案和恢复条件。

## 可测试性

- 为核心功能分配编号，使每条验收标准能回溯功能和场景。
- 用“给定条件 → 执行动作 → 预期结果”描述行为，明确通过与不通过的边界。
- 把“快速”“稳定”“准确率高”改成可测量的定义；阈值无依据时标“待确认”，不要擅自承诺。
- 性能指标应注明设备与系统版本、输入规模、网络条件、冷启动或热启动、样本量、统计口径及测试方法。
- 收益估算应说明基线、公式、统计周期和数据来源；建议目标与已验证事实分开写。
